Latest release · 23 September 2026

Studio 0.4.12 makes the updater finish what it starts.

“The update downloads and the app does not come back” turned out to be one fault with two halves. Studio left as soon as the download finished, while the installer still had to expand the archive afterwards — quitting at that moment cut the expansion in half and the update was discarded without a word. The installer was also being told not to reopen Studio once it had finished. Both are fixed, and an expansion that simply takes a long time can no longer cost you the update.

23 Sep 20260.4.12

0.4.12 An update that finishes, and an app that comes back

Two reports of the same thing — “it downloads, then nothing” — traced to one hand-off. Update 0.4.11 itself is unaffected: this release is about the mechanism that carries it.

  • Studio no longer leaves too early. On macOS the installer expands the downloaded archive inside Studio's own process, and only then starts the helper that swaps the app. Studio was quitting when the download completed — one step before that expansion — so the archive was cut short and the update thrown away silently. It now waits for the installer's own ready signal, and the Skip button stays available for the whole wait, however long the expansion takes.
  • Studio reopens when the update is done. The installer was being handed an instruction not to relaunch the app, so a finished update left you with a closed Studio and nothing to open. That instruction is corrected: a completed install ends with the new version running.
  • A slow expansion can no longer lose the update. Expanding a 240 MB build takes minutes on an older machine. If that cannot be confirmed, Studio opens anyway, keeps the downloaded update and installs it the next time you quit — rather than closing and leaving you guessing.
  • Everything from 0.4.11 ships here too: six visual archetypes for generation, the section toolbar in the preview, Design Tokens with a measured WCAG reading, and the searchable Studio Guides tab.
23 Sep 20260.4.11

0.4.11 Six directions, one section at a time

The complaint this release answers is the one that matters most to a studio selling sites: two briefs in the same trade came back as the same website. A generation prompt with named visual archetypes fixes the source of that, and the preview gained the controls to keep pushing a site further once it exists.

  • Six visual archetypes, not six palettes. Generation now picks between editorial magazine, bento glass, brutalist kinetic, neo-minimalist, organic clay and retro cyberpunk — differing in type, rhythm, borders, button shape and motion as well as colour, with the chosen archetype's own tokens written into the export.
  • The section toolbar. Select a section in the preview and act on that section: rewrite its copy, change its layout, or open a prompt pre-filled with the section named. Each button writes a sentence into Copilot rather than editing behind its back, so the change takes one credit where it should, arrives as a single undo step, and is refused with a reason when the request does not make sense.
  • Design Tokens with a real contrast reading. Brand colour, surface, section rhythm, button radius and button shadow are editable against the open project and the badge measures body text on surface (WCAG AA), not a decorative pair. Every edit survives a reopen and lands in the exported files.
  • Studio Guides. A searchable offline knowledge base covering design DNA, contrast, SEO launch checks, treating client facts as fixed, static-export rules and prompt craft.
  • Layout commands land on the section you pointed at. "Make the second section floating chips" used to resolve to the last section of that kind — invisible on a site with one of them, and the wrong edit on a site with two.
  • The features now exist in installed builds. Four feature scripts were loaded by the shell and missing from the packaged app, so they worked in development and vanished for anyone who downloaded Studio. The release gate now fails a build whose shell loads a script the packager would not ship.
21 Sep 20260.4.10

0.4.10 A dependable launch and a safer update path

This release is about getting back to work without friction: older machines get a lighter rendering path, optional canvas engines no longer affect the normal shell, and the updater has a bounded hand-off instead of racing macOS.

  • Reliable on older hardware. Studio falls back to software rendering when Electron cannot initialise graphics acceleration, and low-power machines automatically reduce expensive blur, shadow and hover work.
  • Advanced Canvas loads on demand. GrapesJS and VvvebJS remain local and pinned, but they are not loaded during normal startup. Open Advanced Canvas when you need them; if a canvas dependency fails, the main Studio remains usable.
  • Updates no longer race the app. The installer hand-off waits for the archive stage, closes the startup window cleanly and leaves a skip route if a check stalls. Implicit installation on quit is disabled so macOS does not run two installer paths.
  • Signed data-only hotfix channel. Bounded feature flags, copy, template hints and release notes can be verified and applied without replacing executable code. Invalid, expired or unsigned data is ignored and the normal bundled app remains the fallback.
  • Faster navigation. Tab changes use a small compositor-friendly fade instead of snapshotting the whole app, with reduced-motion support retained.

17 Sep 20260.4.7

0.4.7 An updater that finishes

This is a repair rather than a feature, and it is worth explaining because the fault looked like a freeze. On macOS, installing an update means handing the job to the system’s installer, which replaces the app only once the running copy is gone. Studio asked it to install and then never quit — so the installer waited for a process that was never going to exit. Measured on a real machine: eight minutes of nothing, then installation completed six seconds after the process was killed by hand.

  • The app now leaves for its own update. The updater window closes, the process exits, and the installer swaps the app in seconds. Restarting to install an update is a restart again — no force-quit, and nothing to know about how macOS installs software.
  • A stalled update can no longer lock you out. The update check runs before your workspace opens, so anything that hung there meant a window you could not dismiss and no way into your own projects. A few seconds in, that window now offers Skip the update and open Studio: the version you already have opens with your work where you left it, and the update is offered again next time you open Studio. A bad connection costs you a restart, not access.
  • Updates name their version. The prompt that asks you to restart now names the version waiting to be installed, rather than asking about “a new version”.
  • Windows is current again. The Windows build had no release of its own since 0.4.5, and its updater reads the manifest from the newest published release — which the last two releases did not carry, so a Windows install had nothing to find and no way forward. 0.4.7 publishes the Windows installer and that manifest. It is still unsigned, so SmartScreen asks once on install; the note on the download page explains the click.
17 Sep 20260.4.6

0.4.6 A site that answers, and a site that dates itself

Website chatbots are normally a hosted service: an API key, a subscription, per-seat pricing, and every visitor’s question passing through someone else’s server. Everything in this release runs inside the file you export — and keeps working if you stop paying us.

  • Concierge. An “Ask us” panel on the site itself, answering from a knowledge pack you fill in — hours, prices, services, the area you cover, a booking link, plus any question you get asked. It runs in the visitor’s browser: no server, no API key, and nothing leaves the page until someone presses send. It is built to refuse rather than guess, because a chatbot that invents an answer is worse than one that says it does not know — anything it cannot place becomes an enquiry through the form your site already delivers. Choose your own wording for the greeting, every answer, and the reply when it does not know. It doubles as an accessible FAQ, since it is keyboard- and screen-reader-operable and needs no JavaScript-optional rendering.
  • Self-scheduling content. A dated strip above the navigation that is written once and then behaves. Put an offer up with an end date and it removes itself after midnight; add seasonal or term-time hours and they appear on the day. There is no cron job and nothing to remember: content already expired when you export is dropped from the file entirely, and live or upcoming entries reveal themselves in the visitor’s own browser. End dates are inclusive and read as the visitor’s local day, so nothing disappears a day early for anyone in a different timezone.
  • Shared links finally unfurl with a picture. Every site has always generated a share card, but it was handed over as an SVG — and X, WhatsApp and LinkedIn will not render an SVG share image, so most shared links showed a bare title instead. The card is now rasterised to a PNG at export, so a link to your site shows the artwork. The same export pass declares each image’s dimensions, which stops photographs shoving the page around while they load.
  • Site Care. A new view for the part of the job that comes after delivery. It sweeps every project you have shipped and reports what has quietly stopped being true: a date that has passed, a price still beside last year, placeholder or sample text nobody replaced, a section left empty that the next export will fill with stock photos, images missing alt text, and links that point at nothing.
16 Sep 20260.4.5

0.4.5 Licence keys, properly handled

A small release about one thing: the key we issue you. Two faults — one about entering a key, one about keeping it.

  • A licence key could only be entered as the last row of the plan grid, and the Upgrade button that opens that grid is hidden once an account is on a paid plan — so the one person most likely to be holding a key was the one person with no visible way to type it in. Settings now offers Redeem a licence key under Plan & billing, on every plan, with the referral box beside it. Verification is unchanged; only the door is new.
  • A key issued to never expire was safe from a cancellation but not from a renewal. Any paid event from the payment provider relabelled the entitlement and copied the subscription’s period end onto the key, so a lifetime licence quietly acquired a date it had never been given — and the cancellation after that read as revoking something that was never revocable at all. A licence now outranks a subscription on renewals too: it keeps its own tier, the tier may only move upward, and no expiry is written onto it. Billing, the customer portal and your receipts are untouched.
16 Sep 20260.4.4

0.4.4 Does it understand what you asked?

Seven changes to one question: whether Studio acts on what you said or merely on the words you used. A refusal stops being an instruction, a scope stops being dropped, undo stops being wholesale — and the moment a site goes live is gated rather than hoped for.

  • The end of opposite-day edits. “Do not make it dark” switched the site to Midnight; “I don’t like the editorial look” applied it; “not the candy palette” switched to Candy. A message is now read once for what it is — request, refusal, rejection, praise, description or question — before anything is planned. A design change happens only when one was asked for, and a refusal is answered with alternatives the engine can actually run, never with the palette that just failed its own contrast check.
  • Scope and limits, read as written. “Make the pricing and faq sections consistent” names two places and one instruction, and used to leave the faq silently alone — so the client believed it was handled. “Every section” was dropped entirely. Now a scope word becomes one edit per section, and only where the write actually lands: a map, embed or countdown keeps its content elsewhere, so rewriting it would have taken a credit and changed nothing visible. “Make it more premium but keep the words” is honoured instead of dropped, and the copilot carries an instruction forward (“same for the FAQ”) while pointing at a section by position — refusing a target it cannot resolve rather than quietly editing the one it was already on.
  • Undo that leaves the rest of your work alone. ⌘Z walks backwards a step at a time, but the sentence you type is “put the colours back”, and answering that with “I undid your last change” asks you to remember what order you did things in. A change is not one thing — “make the hero punchier and switch to ocean” moved two independent paths — so the copilot now works in paths, restoring the most recent change to the one you named and leaving every later change intact.
  • Publish is gated on the failures that only exist live. Two pages exporting to the same file (the zip is valid, one page is simply missing), a menu link to a page that was never made, an enquiry with nowhere to go, an insecure http:// destination, a blank description, nothing to publish at all. Each is visitor-visible and invisible everywhere else, and each now stops the button with a reason.
  • Sites that stay true once you have moved on. A new audit asks what no other one asks — is this still true? Placeholder copy never filled in, our own template’s sample address and phone number, an event date that has passed, last year’s price beside your money, # links, images with no alt. It reports what is not the owner’s rather than what is blank, because the renderer substitutes template samples rather than leaving a section empty.
  • Smaller, but everywhere: free-tier sites carry your own referral link in the badge, so every site you sell recruits for you, and Pro+ exports ship no badge styles at all; generated sites gained animated backgrounds that bind to your palette and honour motion settings; the wheel’s grand prize is now a month of Pro+; the free tier went from 3 AI credits to 7; and “Report a Bug” no longer opens a 404.
  • Billing moved to Dodo Payments, and the account binding moved off the client. Stripe’s payment links carried the account id in a query string anyone could edit, so Pro could be bought for — or as — somebody else. Checkout now reads your account from your verified sign-in instead, and the webhook verifies Dodo’s signature before granting anything.

0.4.3 Exports that prove themselves

Ten upgrades to one thing: the folder a client walks away with. It is faster, usable without a mouse, right to its edges — and it now comes with the evidence to back it up.

  • A delivery report and a manifest in every export: what was measured, what is worth fixing, and a SHA-256 for every file. Anyone you send the folder to can confirm it is unaltered rather than taking your word for it.
  • A share image per page, drawn from your own palette, so a link unfurls as the page it points at. A mistyped URL lands on a 404 wearing the site’s own navigation, not the host’s.
  • Host policy files, security headers included — so a site is hardened from the first upload rather than depending on a chat message about which boxes to tick.
  • Images offer the browser a smaller file wherever the host can resize, so a phone stops downloading a desktop-sized picture. Keyboard visitors get a skip link, a focus ring the site’s own styles cannot remove, and navigation that says which page they are on.
  • Your design system exports as CSS, JSON and a working Tailwind config. Copy is read for clarity, and every link, anchor and asset is resolved before you send it — five real defects were found in our own export while building this, including a Contact link that led nowhere.

0.4.2 Client edits, change notes & measured speed

Client feedback no longer only describes what should change — it makes the change. And when you send the next link, you can prove what you did.

  • Feedback that makes the edit: importing a client’s notes now tells you what Studio can do about each one before you click — a shorter feature list, a dropped section, a rename, a reorder or a corrected email all land in one edit.
